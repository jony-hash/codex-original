# Delta、One Gate 与 Codex 交接

本文件只规定如何把一项已决定的工作交给本地 Codex。项目事实以本地 `AGENTS.md`、源码、数据、模型和正式结果为准；云端对话及 Sources 只是规划材料。

## 执行原则

- 每项工作只保留一个最终科学问题和一个会改变下一步的 Gate。路径核对、数据角色、冻结组、负控、恢复和资源检查是同一任务的内部检查，不另设 Gate。
- `MODE=IMPLEMENT` 授权提示中明确列出的动作，不改变科学问题或阈值，也不自动授权后继实验。
- 预检、训练、测量和恢复不设墙钟上限。记录耗时与资源作观察；用户批准的更新次数、样本和科学阈值保持不变。
- 不要求源码、dirty patch、checkpoint 或 manifest 摘要相等来准入或恢复。用明确路径，核对实际加载的模型、配置、步数、优化器状态、样本行、数据角色和冻结状态。旧摘要仅作历史记录。
- 普通工程问题在原授权内修复，并复测受影响的生产路径；不设修复次数配额。有效测量不足或无效时，不作科学结论。
- 保留数值有效性、评价器隔离、硬件安全、checkpoint 恢复和已有产物。不得为减少检查而缩减科学工作量。

## 本地执行顺序

1. 查看根 `AGENTS.md`、适用的 scoped 指令、当前状态和最少量相关证据。
2. 核实任务所需的输入路径和实际身份；未知事实先定向查询，不用自动 latest 替代。
3. 做覆盖本任务关键生产行为的最小预检。长训练按根 `AGENTS.md` 检查真实更新、冻结组、负控和恢复。
4. 执行已授权动作，保存完整测量。工程错误修复后重测受影响路径；资源与数值安全仍按真实硬件情况处理。
5. 用证据更新任务报告及本轮允许修改的状态摘要。保持历史失败状态和产物不变。

`INVALID_HARNESS` 表示测量无效；`VALID_FAILED` 表示完整有效测量未过科学标准。前者不是科学负结果，后者阻止合同规定的下游动作。工程修复完成后仍需验证，不能仅凭“修过了”报告成功。

## 简短交接格式

```text
MODE: VERIFY | PLAN | IMPLEMENT | REPORT
OBJECTIVE: 一个决策问题
FACTS: 已有结果和本地需要核实的事实
INPUTS: 明确的模型、数据、配置和结果路径
GATE: 一项最终指标或决策规则及其消费者
AUTHORIZATION: 允许做什么
BOUNDARIES: 固定的更新数、样本、数据角色和禁止动作
ACCEPTANCE: 必须保存和核对的最终结果
STOP: 完成后的停止点；不自动启动后继任务
```

仅写会改变本轮行为的信息。不要复制整个项目历史、摘要表、重复 Gate 或无消费者的哈希清单。需要历史细节时引用归档文件或正式结果路径。

## Codex 反馈

```text
结果：完成 / 有效未通过 / harness无效 / 阻断
本地状态：分支、HEAD、dirty范围
完成：改动、测量和终态
验证：实际执行的聚焦测试与检查
剩余风险：只列未验证且会改变结论的事项
下一步：一个建议或 NONE；不得自动执行
```

Sources bridge 的文件同步和上传规则见 [`chatgpt_codex_workflow.md`](../chatgpt_codex_workflow.md)。本地交接不触发自动上传、commit 或下一项科研工作。
